## 3. 近期文件夹与状态规则

### 3.1 列表规则

- 数据来自当前配置里的同步空间，包含等待接受和其他非活动空间，并非只显示“最近成功同步过”的文件夹。
- 按最近成功同步时间降序排列，最多显示 8 项。
- 当前运行期优先使用内存中的最近成功同步时间；没有时读取保存的基线文件修改时间。
- 没有成功同步时间的空间排在已同步空间后面。
- 时间相同时按名称排序，再按 ID 排序，保证顺序稳定。
- 文件夹名称中的连续空白合并；超过 48 个 Unicode 字符时截为前 47 个加省略号。
- 特殊字符 & 以字面含义显示，不当作菜单助记键。
- 固定菜单宽度下，还可能按可用显示宽度进一步省略。
- 一级列表不展示完整路径、对端设备名、文件数或进度条。
- 同名文件夹目前无法通过一级菜单名称区分。
- 每次打开菜单重新读取状态；菜单保持展开时不会实时重建列表。
- 当前没有“置顶”“隐藏最近项”“修改显示数量”等设置。

### 3.2 文件夹子菜单状态与禁用条件

| 条件（按判断优先级） | 状态行原文 | 立即同步 | 打开文件夹 |
| --- | --- | --- | --- |
| 未处于活动状态，或没有已配对对端 ID | 等待配对或接受邀请 | 禁用 | 可点击 |
| 活动空间正在同步 | 正在同步… | 禁用 | 可点击 |
| 活动空间上次同步失败 | 同步失败 · 请在控制台查看 | 可点击，允许重试 | 可点击 |
| 活动空间没有成功同步记录 | 等待首次同步 | 可点击 | 可点击 |
| 活动空间已有成功记录 | 最近同步 · MM-DD HH:mm | 可点击 | 可点击 |

- 日期使用本机时区，当前不显示年份或“几分钟前”。
- “立即同步”不因对端当前离线而提前禁用；连接失败后反馈错误。
- “打开文件夹”不在绘制菜单时检查目录是否存在，点击后才检查。
- 托盘没有同步开关、暂停全部、取消单次同步、移除同步空间、重命名或冲突合并入口；这些不能视为现有菜单能力。
- 托盘退出不会自动关闭浏览器页面；已打开页面之后可能显示服务离线。
- 有同步进行中时退出也没有确认弹窗，当前不提供“完成后退出”。

### 3.3 通知与错误反馈

| 情况 | 当前反馈 |
| --- | --- |
| 手动同步开始 | 系统通知：“正在同步 ‘文件夹名’…” |
| 手动同步完成 | 系统通知：“‘文件夹名’ 同步完成” |
| 同步失败 | 系统通知：“‘文件夹名’ 同步失败：错误详情” |
| 目录无法打开 | 系统通知：“无法打开文件夹：错误详情” |
| 托盘菜单无法打开 | 尝试显示系统通知：“无法打开托盘菜单：错误详情” |
| 默认浏览器启动失败 | 写程序日志；目前没有对应托盘错误对话框 |
| 应用启动失败 | 启用托盘模式时显示 Windows 错误对话框 |
| 系统通知被关闭 / 勿扰 | 系统可能不显示提示；不影响后台动作执行 |

所有这些系统通知目前使用“PolySync”标题和同一种信息通知类型，错误尚未单独换成错误级别图标。通知使用有限长度文本，多条快速发生时可能只看到最后一条。随传通知点击已绑定对应网页记录；原同步通知没有专属记录路由。图标没有进度环、红点或待处理数量。

“同步完成”代表服务调用成功返回，当前托盘没有额外区分“同步结束但有冲突待处理”；此处文案与状态值得调整。

## 4. 当前 UI 规格（工作区实现）

### 4.1 整体方式

使用 Windows 原生弹出菜单和子菜单，在原生菜单项上自绘背景、文字与选中态；不是网页浮层，也不是独立的 WebView 窗口。

因此菜单打开、级联展开、关闭以及外框的部分行为仍由 Windows 管理。当前没有自定义菜单外轮廓圆角、毛玻璃、阴影参数或跨平台一致的菜单窗口。

### 4.4 DPI、状态与动效

- 当前工作区开启 Per-Monitor V2 DPI 感知，在显示菜单前将隐藏的所属窗口移动到鼠标所在显示器位置，再读取该显示器 DPI。
- 字体、行高、留白按 DPI 创建与绘制，避免整张低分辨率菜单被 Windows 放大。
- 175% 缩放对应 168 DPI；此前独立预览中已读到实际菜单为 168 DPI，但这不等于完成所有多显示器组合的视觉验收。
- 当前配色固定为浅色，没有跟随系统深色模式，也没有单独实现高对比度主题适配。
- 鼠标悬停或键盘选中使用相同的浅绿色圆角背景；不可用项不显示可操作的选中态。
- 托盘没有应用自定义动画；菜单动画受 Windows 原生菜单行为和系统设置影响。
- 没有网页式的进度条、按钮涟漪、弹簧展开动画或可拖拽面板。

### 5.1 级联菜单细节

```text
正在传输 · 1 ›
  设备名 · 当前状态 ›
    查看进度
    取消传输

最近收到 ›
  设计说明.pdf ›
    来自 另一台电脑                         [不可点击]
    另存为…
    打开所在文件夹
    查看详情
```

这些菜单使用同一套原生鼠标、右键选择、方向键、Enter 和 Esc 规则。内容在每次打开菜单时刷新；展开期间不动态重建，操作执行时后台再次验证任务和文件状态。

### 5.2 通知与退出

- 完成和失败结果会尝试显示 Windows 通知，点击随传通知打开对应任务。自动接收不会请求逐批确认，也不会自动执行文件。
- 系统勿扰模式可能抑制通知；工作台记录始终是查看结果的入口。大量同时发生的通知可能合并为最后一条。
- 当前尚未根据网页是否可见抑制重复通知；没有已读红点、进度环、动态托盘数量或按设备接收开关。
- 退出确认仅覆盖随传任务；确认后取消工作并释放连接。再启动时不会续传未完成任务。
- 原生通知点击和保存对话框的完整人工操作验收仍见实施记录中的待验证项。

## 7. 后续验收清单

- 各入口指向正确页面/具体记录；网页已开和未开均可使用。
- 菜单展开、键盘方向键、Enter、Esc、点击外部关闭及右键选择正常。
- 不可操作项正确禁用；离线、随传接收关闭、同步邀请等待接受、同步中、文件丢失均有可理解说明。随传没有等待接受状态。
- 多个同名或长名称条目仍能区分，文字不越界。
- 100%、125%、150%、175%、200%、250% 缩放，以及不同缩放显示器之间切换。
- Windows 深色、高对比度、菜单动画关闭、键盘和屏幕阅读器专项检查。
- 所有传输测试使用测试设备、临时目录；另存覆盖和清理有明确确认语义。
- 退出关闭连接与图标并释放端口；重新启动可恢复历史记录。
- 不因点击菜单新增同步关系；随传仅允许身份匹配的已配对设备在接收开关开启时自动投递，不需要逐次人工确认。
- 验证接收开关关闭时发送方获得明确原因；未配对设备不能投递；网页关闭但后台运行时仍可自动接收。
- 现状章节中的同步邀请确认不受随传接收方式调整影响。
