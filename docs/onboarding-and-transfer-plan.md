# 新手引导与随传工作台方案

更新日期：2026-09-08  
状态：第一版已写入工作区，尚未发布；验证结果和受环境阻碍的实机项目见实施记录。  
托盘完整清单与 UI 调整表见 [托盘交互与 UI 规格](tray-interaction-spec.md)。

## 本轮实施结果

已实现五步新手引导、随传工作台、可信设备自动接收、暂存设置，以及 Windows 托盘入口。收件和发送记录合并在“接收与发送”列表中。

- 新手引导提供首次邀请、上一步/下一步、跳过、Esc、焦点恢复和“使用引导”重看；按浏览器保存 v1 状态。弹窗未关闭时等待，不丢弃表单。
- 随传先把浏览器选择的文件流式交给本机后台，再由后台通过已配对公钥校验的 TLS 连接发送。页面显示“已交给后台”后才可放心关闭。
- 已配对设备默认直接投递；接收开关关闭后拒绝新任务，已有任务继续。没有“待接收请求”。
- 每批 1–128 个普通文件，合计不超过 16 GiB；本机最多 4 个活动任务。连接超时 8 秒，上传/传输期限 2 小时，未开始上传的准备任务 2 分钟后取消。
- 接收暂存默认位于数据目录的 inbox；发送缓存位于 transfers/outgoing，记录位于 transfers/records。每任务独立目录，文件增加编号避免重名覆盖。
- 暂存位置只影响新接收任务；旧任务保存原路径。检查暂存与同步根目录重叠，切换时不自动搬移或清理旧文件。
- 完整文件通过 SHA-256 校验后可另存或打开位置。另存调用本机对话框、复制并保留原件，覆盖由对话框确认。
- 移除记录默认保留文件；额外勾选后删除该任务暂存文件。重发创建新任务，依赖原发送缓存，缓存缺失时需重新选文件。
- 取消/失败保留已完整校验的文件，清理未完成部分；异常重启将活动记录标为中断，不自动续传。
- Windows 托盘保留同步操作，增加发送、工作台、活动任务、最近 5 个收件、设置、使用引导；有随传任务时退出会确认。

验证详情及环境限制见 [随传与引导实施验证](transfer-implementation.md)。文件夹传输、离线排队、断点续传、速度/剩余时间、自动清理仍不在第一版范围。

## 1. 目标与范围

让第一次使用的人理解设备配对、文件夹同步和后台运行；为临时跨设备发送文件提供独立的“随传”工作台。

| 用途 | 同步 | 随传 |
| --- | --- | --- |
| 用户目标 | 两端文件夹持续保持一致 | 本次把文件交给另一台设备 |
| 建立长期关系 | 建立同步空间 | 只建立传输任务 |
| 之后修改或删除源文件 | 按同步规则传播 | 不影响对方收到的文件 |
| 接收位置 | 约定的同步文件夹 | 用户设置的暂存目录 |
| 接收后的处理 | 在同步文件夹管理 | 在工作台另存、打开位置或清理 |

沿用绿色品牌、原生 HTML/CSS/JavaScript 和现有配对、加密连接能力，小步实现，不迁移 UI 框架。本文把“随传”作为暂定名称。

## 2. 新手引导

### 2.1 入口与形式

- 首次进入网页时显示轻量邀请：“花一分钟，认识 PolySync”，提供“开始引导”和“稍后”。
- 引导在实际页面上进行：目标区域高亮、附近显示说明气泡，其余区域适度弱化。
- 每步显示“第 N 步 / 共 5 步”，提供上一步、下一步和跳过；最后一步为“完成”。
- 在帮助入口提供“重新查看新手引导”。
- 引导只解释操作，不代替用户发起配对、批准请求或发送文件。
- 暂定在当前浏览器本地记录完成/跳过状态和教程版本，不要求账号；换浏览器或清除数据后可能再次提示。

### 2.2 步骤草案

| 编号 | 高亮目标 | 气泡标题 | 说明与下一步 |
| --- | --- | --- | --- |
| G-01 | 当前设备卡片 | 这是你的设备 | 查看或修改名称；连接地址可供另一台设备手动连接 |
| G-02 | 添加设备按钮与设备区域 | 连接另一台电脑 | 两台设备启动应用并处于同一局域网；支持自动发现和手动地址 |
| G-03 | 配对入口或配对说明区域 | 先确认，再连接 | 接收方允许请求并显示验证码，发起方输入验证码完成配对；说明已配对设备可直接投递随传文件到暂存区 |
| G-04 | 同步 / 随传入口 | 选择这一次的用途 | 长期保持文件夹一致选同步；临时发送几个文件选随传 |
| G-05 | 后台说明 / 帮助入口 | 关掉页面，也能继续工作 | Windows 可从托盘重新打开、操作或退出；其他平台按实际能力显示说明 |

引导不依赖真实操作完成才能“下一步”。没有第二台设备时，G-03 显示简要配对示意，不展示虚假的真实验证码，也不强制用户留在这一步。

### 2.3 交互与异常

- 气泡优先位于目标旁边，接近边缘时自动换侧；窄屏可放在目标下方。
- 目标不在视区内时适度滚动到可见位置；减少动态效果设置下立即定位。
- 弹窗已经打开时，不叠加第二层教程；暂挂教程，待弹窗关闭后恢复。
- 页面缩放、窗口调整大小或目标位置变化后，重新定位气泡。
- 目标暂不存在时显示替代说明或跳过对应定位，不出现空白遮罩。
- 支持 Tab、上一步/下一步按钮及 Esc 跳过；结束后恢复焦点。
- 不用闪烁和持续大幅运动吸引注意，不遮住当前需要操作的按钮。

## 3. 随传工作台

### 3.1 信息结构

已确定的核心逻辑：**配对时建立信任，随传时直接投递到暂存区，每批文件无需接收方再次确认。** 未配对设备仍须先完成设备配对；文件夹同步邀请的确认流程不变。

主内容区增加“同步 / 随传”导航。随传包含：

| 区域 | 展示内容 | 主要动作 |
| --- | --- | --- |
| 发送区 | 目标设备、待发送文件、数量和总大小 | 添加/移除文件、确认发送 |
| 收件箱 | 已接收文件、发送方、接收时间、暂存状态 | 另存为、打开所在文件夹 |
| 传输记录 | 发送/接收方向、设备、进度、结果 | 取消、查看失败原因、重新发送 |

导航名称、布局形式和是否合并“收件箱 / 传输记录”仍可调整。

### 3.2 发送流程

1. 点击“发送文件”或拖入普通文件。
2. 选择已配对且在线的设备。
3. 检查文件名、大小及总量，移除误选项。
4. 点击“发送”，创建任务；后台验证对端身份、接收设置和暂存条件。
5. 检查通过即开始传输，显示进度和取消入口，无需去另一台设备点击接受。
6. 对方完整接收且校验通过后，显示发送完成。

第一版支持多个普通文件，不支持文件夹发送、离线排队、断点续传。文件夹拖入时明确提示当前限制。网页选文件与拖放属于浏览器上传流程，应流式处理，避免把整个大文件读入内存；具体数据接口在实现阶段确定。

发送前校验文件是否仍存在、是否可读；发送期间文件变化应报告失败，不把未完整交付的文件标为成功。数量、容量与超时采用本页“本轮实施结果”的限制。对端离线、关闭自动接收、空间不足或目录不可写时，向发送方明确报告原因，不转入人工审批队列。

### 3.3 接收流程

1. 后台收到传输任务，验证发送方为已配对设备且身份匹配。
2. 检查是否允许已配对设备自动接收，以及暂存目录权限、可用空间和传输限制。
3. 检查通过后自动接收到暂存目录；工作台显示发送方、文件列表和进度，不弹出接受/拒绝气泡。
4. 接收中的文件使用内部临时名称，不能被当作完成文件打开或另存。
5. 接收完整并通过校验后，进入收件箱。
6. 用户选择“另存为”或“打开所在文件夹”。

网页关闭时仍由后台接收，前提是应用在运行；接收并校验完成后通知“收到 N 个文件”。托盘提供工作台、正在传输和最近收件入口。通知只是补充，收件与任务结果都应在工作台中可见。

接收设置建议：

- “允许已配对设备自动接收”默认开启，在随传设置中可以关闭；这是本机接收策略，不修改配对关系或文件夹同步开关。
- 关闭后不再接收新的随传任务，发送方看到“对方已关闭随传接收”，不出现等待接受队列；已经开始的任务继续，用户可逐项取消。
- 重新开启后允许新任务，之前被阻止的任务需由发送方重新发送，不自动补发。
- 配对说明和新手引导应说明：已配对设备可以直接向暂存区投递文件；取消配对后不再有此权限。
- 第一版先采用本机统一开关，按设备单独授权可后续增加。

### 3.4 暂存目录

- 设置页增加“随传暂存位置”，显示当前绝对路径，允许用户选择其他目录。
- 首次使用提供应用专用默认目录，并在开始接收前可见；具体默认路径待定。
- 更换目录前验证可写性。
- 新目录只用于之后开始接收的任务；进行中的任务和已经收到的文件仍使用原路径。
- 第一版不自动搬迁旧文件；每条记录保存其实际暂存位置。
- 第一版不自动删除暂存文件；工作台提供显式清理入口。
- 多个任务中的同名文件应分别保存，不直接覆盖之前收到的内容。
- 暂存目录不应与同步根目录重叠，避免临时接收文件被意外持续同步；实现时检查并解释原因。

### 3.5 文件操作

| 动作 | 建议行为 |
| --- | --- |
| 另存为 | 在本机弹出保存对话框，复制完整暂存文件到用户选择的位置，保留暂存原件 |
| 保存重名 | 提示改名、覆盖或取消；不得默认静默覆盖 |
| 打开所在文件夹 | 用系统文件管理器显示实际存储位置，条件允许时选中文件 |
| 移除记录 | 只删除工作台记录；如暂存仍存在，应说明后续清理方式 |
| 删除暂存文件 | 明确说明删除对象，确认后清理文件；已另存的副本不受影响 |
| 文件已不存在 | 保留可理解的状态，禁用依赖原文件的操作，仍允许移除记录 |
| 取消传输 | 停止本任务、清理未完成文件，保留“已取消”记录 |

“另存为”针对运行 PolySync 的本机。若允许从其他电脑访问控制台，需要避免用户误以为保存到了浏览器所在电脑；第一版沿用本机控制台的使用前提。

### 3.6 状态与反馈

发送状态：待发送 → 连接与接收条件检查 → 传输中 → 对方校验 → 已完成。  
接收状态：身份与接收条件检查 → 接收中 → 校验中 → 已接收。  
异常状态：接收被阻止（设置关闭、未配对或条件不满足）、已取消、已超时、中断、失败、暂存文件已丢失。没有“待接受”或用户逐次“拒绝”状态。

第一版优先准确显示字节进度；速度和剩余时间可在稳定后添加。多文件任务记录每个文件的结果，部分完成不能合并显示为“全部成功”。首次实现的重试可重新发起任务，不宣称断点续传。

### 3.7 实现边界

- 复用已有配对身份、公钥校验和加密连接；新增独立传输操作与任务记录。
- 随传不修改同步空间、共同基线或冲突处理规则。
- 传输和校验采用流式处理；临时文件与最终完成文件分离。
- 远端文件名只作为显示名称和经过验证的本地名称，不能用于任意路径写入。
- 任务记录持久化；应用重启后，未完成任务标为“中断”，暂不自动恢复传输。
- 退出应用时取消进行中的任务，记录结果并释放连接。
- 已配对设备默认免逐次确认，自动接收到暂存区；未配对或身份不匹配的设备不能写入。
- 自动接收只表示保存文件，不自动打开或执行文件，也不替用户另存到其他位置。
