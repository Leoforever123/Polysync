# 轻量常驻：后续实现思路

本轮仅完成安装和更新基础，不改变现有定时同步算法，不宣称已降低常驻内存。后续以“关闭网页后的 Go 后台进程”为主要预算，分别测空闲、配置少量/大量文件、文件修改后的回落、传输峰值；浏览器、系统缓存、临时安装 helper 分开记录。已有测量见 [内存基线](memory-baseline-2026-09-14.md)。

## 文件变化驱动同步

建议顺序：启动先建立监听，再校对一次目录 → 收集变化 → 短时间合并重复事件 → 仅对受影响路径检查 → 使用现有冲突、校验和历史逻辑同步。同步期间新事件留给下一轮；离线设备在重连时补齐，不反复忙等。

监听事件是“需要复查”的提示，不能直接视为确定的文件内容或删除操作。编辑器常用临时文件替换；大文件可能仍在写入；根目录可能暂时离线。必须保留稳定性检测、重命名处理、临时文件过滤，以及根目录不可用时禁止误删对端的保护。

Windows 可使用 ReadDirectoryChangesW。该接口支持子目录监听，但缓冲溢出会丢失明细，需要重新枚举目录。因此建议保留低频校对和事件溢出时的完整校对，而非彻底取消兜底扫描。见 [Microsoft API 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw)。跨平台适配时还需评估 Linux 监听数量上限、macOS 事件合并、网络盘行为，限制内存中待处理路径集合的大小，溢出后标记整目录待校对。

## 常驻和传输内存

先从采样确认长期存活对象：目录清单、对象索引、任务历史、goroutine、定时器和网页关闭后的请求。设定可复现基线，逐项降低；避免为了强制压低显示数字而频繁 GC，影响交互和吞吐。

文件传输当前已有流式路径，后续“文件块”主要用于断点续传、差量传输和限制并发工作集，不能简单等同于当前整文件驻留内存。先找出实际峰值来自扫描清单、浏览器上传、冲突合并还是缓存，再决定分块层。块元数据也要有预算，避免百万小块成为新的常驻负担。

## 右键随传

后续可增加可选的“用 PolySync 发送”：资源管理器传入文件路径，小型一次性入口通过本机 IPC 唤醒现有进程，弹出设备选择；后台未运行时启动它。先保持显式选设备和发送反馈，不默认发往某个设备。注册范围和 Windows 11 菜单兼容性需要单独验证；优先评估按用户注册，只有系统范围功能确需提权时才请求管理员权限。

## 协议扩展

把设备发现、身份验证、任务队列与传输通道拆开定义接口，保留当前 TCP 通道。蓝牙可作为后续通道，但先验证吞吐、重连和平台权限，不影响已有快速局域网传输体验。本阶段不添加常驻蓝牙扫描器。
