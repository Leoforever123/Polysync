## 外置盘掉线保护

PolySync 会自动记住每个同步文件夹的身份。拔出磁盘后，只有使用该磁盘的文件夹会显示「已暂停」。对端文件和此前的同步记录都会保留，其他文件夹仍可同步。同一盘符或挂载路径出现另一块盘时，系统会继续等待原盘。

系统结合本地隐藏标记和操作系统提供的磁盘、目录标识核对身份。请保留同步目录中的隐藏标记。若文件系统只提供标记作为判断依据，连同隐藏标记做出的完整克隆可能与原盘无法区分。

把原盘接回原路径后，系统会自动重新检查文件夹。开启自动同步的文件夹会继续同步，手动模式下被掉线中断的任务也会重试。离线期间在对端保存或删除的文件按原有同步规则处理。在已识别的原盘上主动清空文件夹，仍会同步这些删除。

## 从旧版本升级

建议先在使用外置盘的设备上升级。沿用原安装渠道和数据目录。旧版本没有保存磁盘身份，首次绑定只能核对上次同步记录的文件内容。若另一份副本完整复现这些文件和内容，旧记录也会与它匹配。升级时请接回原盘。目录核对成功后，系统自动完成绑定。如果旧目录为空、缺少同步记录，或上次记录的文件已经改动，系统会暂停。确认原盘已经接回仍未恢复时，可保留两端的文件，重新邀请该文件夹。

## 验证范围

Linux 使用独立挂载命名空间和两块临时文件系统，实际卸载并重新挂载同一路径。分别用原双端协议和多设备文件夹协议建立 TLS 配对，检查空挂载点、带完整文件和标记副本的替代盘、原盘返回后的自动同步及对端的实际文件。另验证了计划生成后切换磁盘、替代盘在位时重启，以及其他文件夹在暂停期间照常同步。

两端均运行新版，以及新版连接已发布的 v0.5.2，均实测了这两种协议。另用两个 v0.5.2 进程先建立同步记录，在原盘已卸载时升级其中一端。新版本在接回原盘后自动识别目录，并接收旧版对端离线期间的修改。

Linux 双端挂载回归在 Go 竞态检测下连续通过五轮。Ubuntu DEB 和 Arch 安装包均完成 v0.5.2 安装、升级到 v0.5.3、重启及卸载测试，设备身份、配对、同步配置和用户文件均保留。

复跑 Linux 的真实挂载用例时，在仓库根目录执行以下两条命令。需要可用的用户与挂载命名空间，以及 `mount` 和 `umount`。普通 `go test ./...` 使用临时目录切换模拟对应情形。

```sh
mkdir -p .cache && go test -race -c -o .cache/service-volume.test ./internal/service
unshare --user --map-root-user --mount --propagation private -- env POLYSYNC_TEST_REAL_MOUNTS=1 .cache/service-volume.test -test.run '^TestExternalVolume' -test.v
```
