# PolySync 基础风险修复记录 · 2026-09-24

依据 2026-09-22 设计报告 v1.1。本轮修复共享核心与 Android 的明确缺陷，保留工作区原有未提交修改；没有提交、推送或正式发布。Android 调试包版本为 0.5.0-dev.3（versionCode 3）。

## 修复与边界

| 报告项 | 本轮结果 | 尚存边界 |
| --- | --- | --- |
| R04 冲突恢复内存 | 本地/远端版本改为 64 KiB 缓冲流式写入临时文件，校验大小和 SHA-256 后归档旧文件并替换；服务停止能取消读取；解决冲突与同步共用空间锁，释放后才启动后续同步 | 16 GiB 文件上限保留；仍需临时磁盘空间与旧文件归档；不是块级差量或断点续传 |
| R05 接入资源 | 每个核心最多 32 个入站连接；超额立即关闭；TLS 握手 8 秒；hello 与后续配对/邀请控制阶段共用一次 8 秒绝对期限；hello、配对申请/确认帧在分配正文前限制为 64 KiB | 已授权同步的大清单仍可到 128 MiB，尚无全局扫描预算/对端公平连接配额；不能称为完整抗拒绝服务方案 |
| R07 后台活动检查 | Go 增加 HasActiveWork，安卓每十秒直接调用；不再请求完整 status/transfers，不生成 JSON、不克隆历史、不检查收件文件是否存在 | 检查仍会遍历内存中的随传记录；历史总量、分页和 O(1) 活动索引另行处理 |
| R08 主动停止被重建覆盖 | 页面停止及通知停止保存用户选择；Activity 重建或重新打开应用不会自行启动；用户点击启动/重新发现会恢复开启意图 | 系统停止和十分钟空闲停止仍沿用原策略；不是开机启动或系统杀进程后自动恢复 |
| R09 导入导出未计入活动 | 原生 work 在排队前登记，完成/异常/投递失败均释放；后台检查计入排队及运行任务；用单调时间，结束后重新开始空闲计时；检查异常不会被当成空闲 | 用户主动停止及系统超时仍能停止服务；不承诺 URI 提供器永不阻塞，也未覆盖所有系统强杀恢复 |
| R17 发现记录阻塞整批更新 | 单个无效条目被过滤，有效条目照常更新，丢失设备照常移除；返回拒绝数量；安卓不再静默吞掉更新失败，而在发现状态显示提示 | 整体 JSON 解析失败、超过快照上限仍拒绝整批并保留旧快照；128 个发现名额未保留已配对设备专属额度 |
| R18 配对申请无界 | 待处理申请上限 32；同来源 IP 每个一分钟窗口最多接受 8 次；来源计数表最多 64 项；到期惰性回收；同请求 ID/设备 ID/公钥重复申请不覆盖原请求；限制身份字段长度 | identify 的公开元数据语义未变；没有对所有操作做每 IP 速率限制；上述数字为本轮可调整的工程默认值 |
| R19 错误被当成正常状态 | 冲突记录读取失败返回 HTTP 500 和明确错误，移动桥接同样返回错误，不返回成功的部分/空冲突列表 | 当前采用整次状态请求失败，尚未实现按条损坏隔离及 UI 保留其他状态的独立告警面板 |

另修正：文本冲突预览通过同一文件句柄和限长读取，防止 stat 后文件增长绕过 5 MiB 限制；冲突副本清理失败不再被忽略或标为已解决。

上述修复不等于 R01–R22 全部关闭。十分钟空闲停止仍存在，Android 系统目录自动同步、全平台常驻内存基线、历史清理策略、安装签名与完整升级验证等仍需后续处理。本轮没有用停止服务换取更低的内存数字，也没有新增定期文件扫描。

## 验证

所有文件测试使用临时目录，网络测试使用回环连接，不使用用户同步目录。

- Windows Go 1.27.1：`go test ./...`、`go vet ./...` 通过。
- WSL：`go test -race ./internal/service ./internal/discovery ./internal/protocol ./internal/syncer ./mobile` 通过。首次临时脚本因 CRLF 导致 mobile 路径多出回车而失败，转换为 LF 后重跑通过。
- 网页兼容：`node --test tests/ui.test.cjs` 9 项通过；`node --check internal/webui/static/app.js` 通过。本轮未改网页布局。
- Windows amd64、Linux amd64/arm64、macOS amd64/arm64 核心构建通过；编译成功不代表这些平台的托盘和原生界面已完整验收。
- Android：Kotlin 单元测试 4 项（文件名 2 项、后台策略 2 项）、debug APK、instrumentation APK 及 lint 构建通过；最终包已安装到手机；`CoreDeviceTest`、`AppLifecycleTest`、`DesignDeviceTest` 合计返回 `OK (5 tests)`，耗时 147.487 秒。
- 真机覆盖：十次核心重启保持身份、2 MiB 随传字节一致、工作区同步和路径越界拦截、三轮前台服务启停及端口释放、主动停止后 Activity 重建保持停止并允许明确重启、三个导航页与未变化控件的轮询稳定性。批次返回较慢，期间按既有 vivo 测试方式将应用带到前台；未修改省电或安装安全设置。新增的停止/重建/明确重启用例随后单独复核，另返回 `OK (1 test)`，66.03 秒。
- 新增用例：32 MiB 合成冲突对象恢复、64 KiB 最大读取块、哈希/长度不符及取消不覆盖原文件/不生成归档/不残留临时文件、空间互斥与后续同步；连接上限/超时/恢复与端口释放；配对去重/来源限额/过期恢复；混合发现快照；错误状态 API；不依赖磁盘冲突列表的活动检查；原生空闲策略及主动停止后 Activity 重建。

大文件用例验证缓冲和数据完整性，不是常驻 PSS/RSS 基准，也不是 16 GiB 极限测试。安卓长时间真实 URI 导入/锁屏、24/72 小时驻留、完整 mDNS 多网络恢复及桌面 MSI 升级没有因这些单元测试而自动获得通过结论。
