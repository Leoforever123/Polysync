# PolySync 架构与协议

## 组件

PolySync 被编译为单个可执行文件，静态资源通过 `embed` 打包进去。

- `cmd/polysync`：进程生命周期、信号处理、控制台和浏览器启动。
- `internal/discovery`：`_polysync._tcp.local` mDNS 发布、浏览和在线状态。
- `internal/service`：设备身份、TLS、配对、邀请、自动调度、TCP 服务端/客户端、HTTP API 和运行状态。
- `internal/syncer`：目录扫描、SHA-256 清单、三方差异规划、安全文件替换和历史归档。
- `internal/protocol`：长度前缀 JSON 控制帧和紧随其后的二进制文件流。
- `internal/store`：Ed25519 私钥、已配对设备、同步空间、内容对象、冲突和每对设备的共同基线。
- `internal/webui`：无构建依赖的本地 Web 控制台。

每个同步空间用独立互斥锁串行化。不同同步空间可以同时同步；同一个空间的入站和出站会话不会同时修改文件。

## 三方差异模型

对每个相对路径比较三份摘要：

- `server`：接收 TCP 连接一端的当前文件。
- `client`：发起 TCP 连接一端的当前文件。
- `baseline`：这两台设备上一次成功完成同步时的共同文件。

规划规则：

| 服务端变化 | 客户端变化 | 结果 |
| --- | --- | --- |
| 否 | 否 | 不操作 |
| 是 | 否 | 服务端内容或删除传给客户端 |
| 否 | 是 | 客户端内容或删除传给服务端 |
| 是 | 是，摘要相同 | 不传输，更新共同基线 |
| 是 | 是，摘要不同 | 创建冲突副本并同步两个版本 |

首轮没有共同基线：只存在于一边的路径复制到另一边；两边同路径摘要不同则视为冲突。

路径是否存在也参与三方判断：baseline 不存在且单边存在表示新建，应复制到另一边；baseline 存在、单边缺失且另一边未变化才表示删除传播；单边删除而另一边修改属于 Modify/Delete 冲突。双方同名新建不同内容属于 Add/Add 冲突。

## 设备发现与配对

mDNS TXT 记录发布设备 ID、友好名称、协议版本、监听端口和 Ed25519 公钥指纹。发现不建立信任，只提供连接候选地址。mDNS 不可用时可以手动输入地址并从 TLS 证书读取设备身份。

发起方建立临时 TLS 1.3 连接并发送长期公钥。接收方必须先在 UI 中允许请求，随后显示服务端随机生成、60 秒有效的六位验证码。发起方输入验证码后，双方使用 Ed25519 对包含双方公钥、随机 nonce 和验证码的 transcript 签名，成功后才保存对方公钥。

已配对连接使用自签名 Ed25519 TLS 证书并固定保存的公钥。双方在 TLS 握手中证明持有对应私钥，因此 mDNS 地址本身不赋予同步权限。

## TCP 同步会话

所有控制帧是 4 字节大端长度加 UTF-8 JSON，控制帧最大 128 MiB。文件内容不做 JSON/Base64 编码，紧跟文件头流式传输。

```text
发起端                                      接收端
  | ---- hello(share, device, port) -------> |
  | <--- challenge(nonce, device) ---------- |
  | ---- sync_request(manifest) ------------> |
  | <--- plan ------------------------------- |
  | ---- file header + bytes (0..n) --------> |
  | ---- uploads_done ----------------------> |
  | <--- file header + bytes (0..n) -------- |
  | <--- transfers_done -------------------- |
  | ---- ack(final manifest) ---------------> |
  | <--- result ----------------------------- |
```

整个会话运行于 TLS 1.3。接收方同时检查客户端证书公钥、设备 ID 和文件夹授权关系；发起方固定接收方已配对公钥。

接收文件时会：

1. 校验相对路径且拒绝路径中的符号链接。
2. 在目标目录创建临时文件并限制读取精确字节数。
3. 计算并核对 SHA-256。
4. 把已有目标复制到状态目录的历史区。
5. 设置权限和修改时间，再替换目标。

只有双方最终文件清单的路径、大小和摘要完全一致，才保存新的共同基线。连接中断或文件并发变化不会推进基线。

## 局域网连接

mDNS 优先提供当前地址，认证成功后也会缓存连接来源 IP 和对端监听端口。自动任务按文件夹间隔轮询；设备离线时保留错误状态并在下一周期重试。

## 冲突对象与解决

每次成功同步的普通文件按 SHA-256 保存到全局去重对象库。冲突记录保存 base/local/remote 三个摘要、冲突类型和设备名称。文本 UI 支持三栏比较、选择任一版本、删除或编辑最终合并内容。解决状态通过下一次同步会话传播给另一台设备；工作区变更随后按普通单边修改同步。
